# لوحة تحليل مبيعات المتجر

## وصف مشكلة البزنس
المتجر يبيع إلكترونيات وأثاث وقرطاسية وإكسسوارات وأجهزة منزلية في 7 مدن أردنية، ويقدّم خصومات متفاوتة. السؤال: **من أين يأتي الإيراد، وهل الخصومات تدفع الزبائن لشراء أكثر أم أنها تقلل أرباحنا فقط؟**

## مصدر البيانات
قاعدة بيانات SQLite اسمها `store.db` (مرفقة بالمشروع) فيها ثلاثة جداول:
- `sales`: 1500 عملية بيع (التاريخ، المدينة، الكمية، الخصم، طريقة الدفع) من 1 يناير إلى 30 سبتمبر 2026.
- `products`: 44 منتجًا (الاسم، الفئة، السعر).
- `customers`: 120 عميلًا (الاسم، المدينة، تاريخ الانضمام).

## المؤشرات (KPIs) ولماذا اخترناها
| المؤشر | لماذا هو Actionable وليس Vanity |
|---|---|
| إجمالي الإيراد (بعد الخصم) | يقيس الهدف الأساسي، ويتغير مع الفلاتر فنعرف أي مدينة أو فئة تحتاج تدخلًا |
| متوسط قيمة الطلب | إذا نزل نرفع البيع المرافق (Bundles)، وإذا ارتفع نعرف أن العروض تعمل |
| الخصومات من المبيعات (%) | يظهر كم نتنازل عنه من إيرادنا، وهو رقم نقدر نتحكم فيه بقرار مباشر |
| متوسط إنفاق العميل | يوجّه ميزانية التسويق بين جذب عملاء جدد أو زيادة إنفاق الحاليين |

استبعدنا مؤشرات مثل "عدد الطلبات الكلي" لوحده لأنه رقم جميل لا يقودنا لقرار.

## هيكل المشروع
| الملف | وظيفته |
|---|---|
| `store.db` | قاعدة البيانات (SQLite) المبنية من الملف النصي |
| `store_db_dump (1).txt` | النسخة النصية الأصلية للقاعدة |
| `cleaning.py` | قراءة البيانات وتنظيفها وحساب الإيراد وكشف القيم الشاذة |
| `week8_analysis.py` | حل الأسبوع الثامن (استكشاف، تنظيف، EDA، اختبار فرضية، اتجاه زمني) كما هو. يحتاج الملف `store_db_dump (1).txt` بجانبه |
| `analysis.py` | الأسبوع التاسع: اختبار الفرضية (كدالة)، تفسير قفزة سبتمبر، وتقسيم العملاء RFM + K-Means |
| `dashboard.py` | لوحة Streamlit التفاعلية |
| `report.py` | يولّد التقرير التنفيذي `executive_report.md` |
| `executive_report.md` | التقرير/الملخص التنفيذي النهائي |
| `requirements.txt` | المكتبات المطلوبة |

## طريقة التشغيل (خطوة بخطوة)
1. ثبّت Python 3.10 أو أحدث.
2. افتح الطرفية (Terminal) داخل مجلد المشروع.
3. ثبّت المكتبات: `pip install -r requirements.txt`
4. (اختياري) شغّل التنظيف والتحليل لترى النتائج مطبوعة: `python cleaning.py` ثم `python analysis.py`. ولرؤية حل الأسبوع الثامن: `python week8_analysis.py`
5. ولّد التقرير: `python report.py`
6. شغّل اللوحة: `streamlit run dashboard.py`
7. سيفتح المتصفح تلقائيًا على `http://localhost:8501`، وإن لم يفتح انسخ الرابط من الطرفية.

## التحديات والحلول
- **أصعب شيء كان القيم الشاذة في الكمية:** وجدنا 12 طلبًا بكميات غير منطقية (مثل 250 دبّاسة). حللناها بطريقة IQR وجعلنا استبعادها خيارًا في الشريط الجانبي، فيقدر المستخدم يشوف الأرقام بوجودها أو بدونها.
- **العربية في الرسومات:** نص Matplotlib العربي كان يظهر مقطّعًا ومعكوسًا، فاستخدمنا مكتبتي `arabic-reshaper` و`python-bidi` لإصلاحه، وجعلنا الصفحة RTL بـ CSS.
- **سبتمبر مرتفع جدًا:** كاد يضلل قراءة الاتجاه، فحللناه بالفئة والمدينة وقيمة الطلب ووجدنا أن السبب كثرة طلبات القرطاسية، ثم عرضناه في اللوحة بدل حذفه.
- **تسمية شرائح العملاء:** K-Means يعطي أرقام مجموعات فقط، فسمّيناها حسب خصائصها (الأبعد زمنًا = خاملون، الأعلى إنفاقًا = كبار) ليفهمها غير التقني.

## لو عندي وقت أكتر
- ربط الإيراد بالتكلفة لحساب **الربح** الفعلي بدل الإيراد فقط، لأن الخصم يؤثر على الهامش.
- مقارنة سبتمبر بسبتمبر السنة الماضية إن توفرت بيانات.
- نموذج توقع مبيعات الأشهر القادمة، وتحليل سلة المشتريات (أي منتجات تُشترى معًا).
- إضافة تنزيل البيانات المفلترة كملف CSV من اللوحة.

## ملاحظات
- العملة غير مذكورة في قاعدة البيانات، افترضنا أنها دينار أردني.
- بيانات الطلبات من رقم 1 إلى 30 تبدو بنمط منتظم (منتجات 1-10 في أول سبتمبر)، وقد تكون بيانات تجريبية، ونوصي بمراجعتها مع صاحب البيانات.
